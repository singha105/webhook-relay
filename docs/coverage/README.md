## Reading these numbers honestly

The total is deflated by two things worth naming rather than hiding:

- **`cmd/api` and `cmd/worker` have no tests**, and they are pure wiring —
  flag parsing, signal handling, and dependency construction. They are covered
  by the fact that `make demo` runs them.
- **`internal/store` sits at ~42%** because it contains many query methods
  reached only by operational paths (listing, pagination, admin queries). The
  paths that matter for correctness — the claim query, idempotency, lease
  handling, the delivery state machine — are covered by integration tests
  against a real Postgres via testcontainers.

`pkg/webhook` is at 100% because it is the one package a third party actually
imports: the signature verification helper. That is where a bug is least
recoverable, since it would be in someone else's codebase.

Every test that touches Postgres or Valkey runs against the real thing in a
container. There are no database mocks in this repository — a mock would have
happily passed the idempotency race that a real Postgres caught on Day 1.
